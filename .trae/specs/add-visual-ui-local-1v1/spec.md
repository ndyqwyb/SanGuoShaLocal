# 本地版三国杀可视化界面 Spec

## Why
当前项目已具备可玩的 1v1 规则与 AI，但主要通过命令行交互，操作门槛较高、状态信息不直观。  
需要一个本地可视化、可点击操作的界面，让玩家更顺畅地进行选将、出牌、响应与结算观察。

## What Changes
- 为现有本地 1v1 对战新增可视化客户端界面（首期聚焦单机本地）。
- 提供完整可操作流程：开始游戏、选将、回合内出牌、响应操作、对局结束与重开。
- 提供核心战场信息展示：双方体力、手牌数、装备、弃牌堆计数、当前阶段、行动日志。
- 新增玩家手牌可点击交互与合法目标提示，非法操作给出清晰反馈。
- 新增 AI 行为可视化反馈（出牌提示、响应提示、伤害与回复结果）。
- 将现有规则引擎与 UI 解耦：通过统一的状态快照与动作接口通信，避免规则逻辑散落到界面层。
- 提供最小动画与节奏控制（非高保真特效）：保证可读性与可操作性优先。

## Impact
- Affected specs: UI 表现层、交互输入层、游戏状态同步层、本地启动流程。
- Affected code: CLI 启动入口、游戏引擎对外接口、事件/日志输出通道、测试与回归脚本。

## ADDED Requirements
### Requirement: 本地可视化对战界面
系统 SHALL 提供本地可视化窗口，支持玩家通过鼠标/键盘完成 1v1 对局全流程。

#### Scenario: 玩家完成一局可视化对战
- **WHEN** 用户从本地入口启动可视化模式并进入对局
- **THEN** 系统展示双方基础信息、当前阶段、可操作区域与日志区域
- **AND** 玩家可通过界面交互完成出牌/结束阶段/响应，并在局终看到胜负与重开入口

### Requirement: 可点击手牌与合法性引导
系统 SHALL 为玩家手牌提供可点击操作与目标选择引导，并对非法操作进行即时提示。

#### Scenario: 玩家出牌合法性校验
- **WHEN** 玩家点击一张可使用手牌并尝试指定目标
- **THEN** 系统高亮合法目标并屏蔽非法目标
- **AND** 若操作不合法，系统展示可理解的错误提示且不破坏当前界面状态

### Requirement: AI 行为可视化反馈
系统 SHALL 在 AI 回合和响应窗口中展示可读的动作反馈，避免“黑盒”体验。

#### Scenario: AI 行动展示
- **WHEN** AI 使用牌或响应牌
- **THEN** 界面实时显示对应动作、结算结果和关键状态变化（体力、手牌数、装备变化）

### Requirement: 界面与规则解耦
系统 SHALL 通过统一动作接口与状态快照机制驱动界面更新，UI 不直接写入底层规则状态。

#### Scenario: 状态同步更新
- **WHEN** 规则引擎完成一次动作结算
- **THEN** 系统产出可供界面消费的状态快照与事件日志
- **AND** 界面据此刷新显示，不直接改写引擎内部数据结构

### Requirement: 可视化模式与 CLI 共存
系统 SHALL 保持现有 CLI 能力可用，并提供可视化模式入口，不破坏原有回归能力。

#### Scenario: 启动模式选择
- **WHEN** 用户启动程序
- **THEN** 系统可选择进入 CLI 或可视化模式
- **AND** 两种模式共享同一规则引擎核心能力

## MODIFIED Requirements
### Requirement: 本地入口行为
系统将“仅 CLI 交互入口”修改为“支持 CLI 与可视化双入口”，默认优先展示更友好的可视化模式（可配置）。

#### Scenario: 用户本地启动
- **WHEN** 用户执行启动命令
- **THEN** 系统可按配置/参数进入指定模式
- **AND** 未配置时进入默认模式并提供切换方式

## REMOVED Requirements
### Requirement: 首期仅文本交互
**Reason**: 文本交互难以满足“可视化、可操作”的体验目标。  
**Migration**: 文本交互保留为兼容模式，用于快速调试与自动化回归；玩家体验主路径迁移到可视化模式。
